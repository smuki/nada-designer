## 1. 接口与数据概况

## 2. 字段元数据模型

每条字段定义包含以下 8 个属性（部分属性可能缺失）：

| 属性 | 类型 | 含义 | 本次数据观察 |
| --- | --- | --- | --- |
| `name` | string | 字段唯一标识，业务代码中作为 key 使用 | 系统字段、`u_` 自定义字段、`E_system_` 预置维度、`AI_`、以及少量中文名（如 `法人实体`、`项目`） |
| `label` | string | 显示名称（中文） | 406 条全部非空 |
| `cnLabel` | string | 中文标签 | 与 `label` 完全一致（0 条差异） |
| `enLabel` | string | 英文标签（多语言/国际化展示用） | 284 条缺失或为空 |
| `active` | boolean | 是否启用 | 全部为 `true` |
| `canAsDimension` | boolean | 能否作为统计/分析/筛选维度 | `true` 101、`false` 149、未声明 156 |
| `ability` | string | 字段所属业务能力/模块 | 空字符串 23 条、属性缺失 246 条、其余见第 4 节 |
| `dataType` | object | 数据类型描述 | 17 种 `type`，详见第 3 节 |

> 注意：`label` 与 `cnLabel` 目前完全重复，但语义不同（显示名 vs 中文标签），代码中建议优先取 `label`，英文环境回退顺序为 `enLabel → cnLabel → label → name`。

## 3. 数据类型体系

### 3.1 基础类型分布

`dataType` 是一个对象，其 `type` 决定字段形态；不同类型还会携带不同的附加属性：

| `type` | 数量 | 说明 |
| --- | --- | --- |

| `text` | 108 | 文本（单行/多行字符串） |
| `money` | 51 | 金额（无 scale/unit，精度与币种由平台与业务约定） |
| `date` | 29 | 日期（yyyy-MM-dd） |
| `list` | 26 | 列表，子元素类型见 `elemType`（ref / complex / attachment / order / 统计汇总类型） |
| `number` | 18 | 数值，`scale` 为小数位，`unit` 为计量单位（%、张、次、人、天等） |
| `boolean` | 13 | 布尔 |
| `dynamic` | 5 | 动态表单：子字段集合由模板决定，接口不展开 |
| `dateRange` | 5 | 日期区间（起止日期） |
| `corporateExpenseCard` | 1 | 易商卡申请组件（专用业务对象） |
| `checkingBillInfo` | 1 | 账单信息组件（专用业务对象） |
| `supplier` | 1 | 供应商（专用业务引用） |
| `splitCalculation` | 1 | 拆分计算组件 |
| `profitAndLossSummary` | 1 | 损益小结组件 |
| `invoice` | 1 | 发票组件（发票信息结构） |

| `reconcileResult` | 1 | 对账结果组件 |

### 3.2 引用类型 `ref` 的实体命名空间

`ref` 字段的 `dataType` 形如 `{ "type": "ref", "entity": "organization.Staff" }`，`entity` 指明引用的实体类型，字段值为实体 ID。本次共出现 **92** 个不同实体（统计范围含顶层字段、列表元素与 `complex` 嵌套子字段），按命名空间归类如下：

| 命名空间 | 出现次数（含嵌套） | 实体数 | 示例实体 |
| --- | --- | --- | --- |
| basedata.Dimension（基础数据维度） | 82 | 48 | basedata.Dimension.法人实体、basedata.Dimension.职级预置、basedata.Dimension.岗位预置 … |
| datalink.DataLinkEntity（业务对象实例） | 29 | 24 | datalink.DataLinkEntity.system_账单、datalink.DataLinkEntity、datalink.DataLinkEntity.b9155d04bebe47e73fc0 … |
| organization（组织架构） | 16 | 2 | organization.Staff、organization.Department |
| basedata.city（城市基础数据） | 7 | 1 | basedata.city |
| datalink.DataLinkTemplate（业务对象模板） | 6 | 1 | datalink.DataLinkTemplate |
| basedata.Enum（枚举） | 5 | 5 | basedata.Enum.InvoiceType、basedata.Enum.PartialPayState、basedata.Enum.CabinType … |
| form.Specification.Versioned（表单模板） | 5 | 1 | form.Specification.Versioned |
| requisition（申请单） | 3 | 1 | requisition.RequisitionInfo |
| pay（支付域） | 3 | 2 | pay.PaymentAccount、pay.PayeeInfo |
| connect.BlockUI（统计区块） | 2 | 2 | connect.BlockUI.APPROVAL_STATISTICS、connect.BlockUI.LOAN_STATISTICS |
| trip（行程） | 2 | 1 | trip.TripType |
| flow.FeeType（费用类型） | 2 | 1 | flow.FeeType |
| flow.Flow（单据） | 1 | 1 | flow.Flow |
| system_支付计划 | 1 | 1 | system_支付计划 |
| basedata.Settlement（结算方式） | 1 | 1 | basedata.Settlement |

要点：

- `basedata.Dimension.*` 是基础数据「自定义维度」（法人实体、成本中心、项目、是否、办公地点等），是 `canAsDimension = true` 的主要来源；
- `basedata.Enum.*` 是平台枚举（发票类型、舱型、席别、部分支付状态等）；
- `datalink.DataLinkEntity.*` 是「业务对象」（数据关联/低代码对象）实例，`DataLinkTemplate` 是对应模板；同一实体 ID 在不同字段中重复出现，说明其按业务对象模板区分子类型；
- `form.Specification.Versioned` 统一表示「模板」（单据模板、费用类型模板、分摊/摊销/行程类型模板），带版本；
- 引用字段只返回实体标识与 ID，**不含选项值/实体明细**，要渲染下拉框必须再调用对应的维度/枚举/业务对象接口。

### 3.3 列表与复合类型

`list` 共 26 个，其 `elemType.type` 分布为：`ref` 6 个、`complex` 10 个、`attachment` 3 个、`order` 1 个、统计汇总类型 6 个。

- **list<ref>**：引用实体列表，如 `travelers`（出行人）、`expenseLinks`（关联申请）、`flowLinks`（单据查询）、`u_资料申请主体`、`budgetAdjustDetails`；
- **list<complex>**：内联复合结构，`elemType.fields` 直接给出子字段的完整定义（可继续嵌套），本次出现 10 处、最大嵌套深度 1 层；
- **list<attachment>**：附件列表，如 `attachments`、`u_银行回单`、`u_退票回单`；
- **list<order>**：第三方订单信息，如 `orders`；
- **统计汇总类型**：`expenseMoneySumByCurrency`、`writtenOffSumByCurrency`、`companyRealPaySumByCurrency`、`payMoneySumByCurrency`、`writtenOffByDetails`、`payMoneyByDetails`——描述「按币种/按明细」的聚合结果，接口未展开其内部结构。

**`dynamic` 动态表单**共 5 个：`feeTypeForm`（费用明细表单）、`tripForm`（行程明细表单）、`apportionForm`（分摊表单）、`amortizeForm`（摊销表单）、`dataLinkForm`（业务对象表单）。其真实字段由对应模板（`specificationId` / `dataLinkTemplateId`）决定，本接口只标注类型，不展开子字段。

### 3.4 数值精度、单位与日期

- `number`：通常带 `scale`（小数位）与 `unit`（单位），如 `taxRate` 为 `scale=2, unit=%`、`apportionPercent` 为 `scale=4, unit=%`、`invoice` 为 `scale=0, unit=张`；
- 少数数值字段 `scale` 或 `unit` 显式为 `null`（如 `detailNo`），解析时需容错；
- `money` 一律不带 `scale`/`unit`，金额的精度、币种分别由平台约定和关联币种字段（如 `receivingCurrency`）表达；
- `dateRange`（5 个）表示「起止日期」，如 `tripDatePeriod`（住宿日期）、`feeDatePeriod`（消费起止日期）、`amortizeDateRange`、`u_受益期间`、`u_出差起止日期`。

### 3.5 专用业务类型

以下类型属于「界面组件/业务对象」级类型，接口只给类型名，不提供内部字段：

| 类型 | 字段 | 说明 |
| --- | --- | --- |
| `corporateExpenseCard` | `corporateExpenseCardForm` | 申请易商卡线下消费 |
| `checkingBillInfo` | `checkingBillInfo` | 账单信息 |
| `supplier` | `checkingBillForm` | 对账单（供应商） |
| `reconcileResult` | `reconcileResultForm` | 对账结果 |
| `invoice` | `invoiceForm` | 发票信息结构 |
| `permitOrder` | `order` | 商旅订单详情 |
| `splitCalculation` | `splitCalculation` | 拆分计算 |
| `profitAndLossSummary` | `profitAndLossSummary` | 损益小结 |

## 5. 字段命名规约与来源

| 命名形态 | 数量 | `name` 示例 | `label` 示例 | 说明 |
| --- | --- | --- | --- | --- |

| 预置维度 `E_system_*` | 8 | `E_system_post`、`E_system_支付计划_legalEntity` | 岗位预置、支付计划_法人实体 | 系统预置维度接入字段 |

判断字段来源时**不要只看前缀**：`u_` 能稳定识别自定义字段，但自定义字段也可能以中文命名（本数据集中 3 条），且个别自定义字段名存在拼写/配置问题（如 `u_二级上级加错`）。

## 6. 可分析维度 `canAsDimension`

- `true`（101 个）：可作为报表分组、筛选条件、看板维度。基本是引用类型：员工、部门、法人实体、成本中心、项目、自定义维度、枚举等；
- `false`（149 个）：明确不可作为维度，通常是金额、日期、明细 ID、动态表单、附件、布尔开关等；
- 未声明（156 个）：响应中没有该属性，建议按 `false` 处理。

## 7. 典型复合结构

### 7.1 费用明细 `details`

```json
{
  "name": "details",
  "label": "费用明细",
  "ability": "expense",
  "dataType": {
    "type": "list",
    "elemType": {
      "type": "complex",
      "fields": [
        { "name": "feeTypeForm", "label": "费用明细", "dataType": { "type": "dynamic" } },
        { "name": "specificationId", "label": "费用类型模板", "dataType": { "type": "ref", "entity": "form.Specification.Versioned" } },
        { "name": "feeTypeId", "label": "费用类型", "dataType": { "type": "ref", "entity": "flow.FeeType" } }
      ]
    }
  }
}
```

（示意，省略了 `active`、`cnLabel`、`enLabel` 等属性）

含义：一条报销单下的多行费用明细，每行由「费用类型」+「费用类型模板」+「动态表单（金额、日期、发票等）」组成。同类结构还有 `trips`（差旅行程）、`apportions`（分摊明细）、`amortizes`（摊销组件）、`linkDetailEntities`（关联明细）。

### 7.2 支付计划 `payPlan`

```json
{
  "name": "payPlan",
  "label": "支付计划",
  "dataType": {
    "type": "list",
    "elemType": {
      "type": "complex",
      "fields": [
        { "name": "dataLinkForm", "label": "业务对象明细", "dataType": { "type": "dynamic" } },
        { "name": "dataLinkTemplateId", "label": "业务对象模板", "dataType": { "type": "ref", "entity": "datalink.DataLinkTemplate" } },
        { "name": "dataLinkId", "label": " 业务对象实例", "dataType": { "type": "ref", "entity": "system_支付计划" } }
      ]
    }
  }
}
```

（示意，省略了 `active`、`cnLabel`、`enLabel` 等属性）

含义：支付计划由「业务对象（低代码对象）」承载，动态表单内容由模板决定。注意 `dataLinkId` 的实体是 `system_支付计划`，与其他 `datalink.DataLinkEntity.*` 命名不同；`label` 中含前导空格（`" 业务对象实例"`），做展示时建议 `trim`。

### 7.3 业务对象关联字段的三种形态

| 形态 | 字段 | 结构 |
| --- | --- | --- |
| 单个业务对象 | `dataLinkId`、`u_出差申请`、`u_关联采购订单` | `ref → datalink.DataLinkEntity.<模板ID>` |
| 业务对象列表（可编辑） | `payPlan`、`u_关联资产入库`、`u_关联出差申请`、`E_system_payment_plan_write` | `list<complex{dataLinkForm, dataLinkTemplateId, dataLinkId}>` |
| 业务对象模板 | `dataLinkTemplateId`、`dataLinkForm` | `ref → datalink.DataLinkTemplate` / `dynamic` |

### 7.4 全部复合结构一览（10 处）

以下字段的 `dataType.elemType.type` 为 `complex`，子字段直接内联在接口响应里（附录只列顶层 406 个字段，嵌套子字段见本表）：

| 顶层字段 | 中文名 | 子字段（name：类型） |
| --- | --- | --- |
| linkDetailEntities | 关联明细(多) | linkDetailEntityId（text）、amount（money） |

## 8. 接入与使用建议（数据观察）

1. **不要写死字段**：235 个 `u_*` 字段（约 58%）来自租户配置，换 corpId 后可能不存在，接入方应把它们当扩展字段处理，按 `name` 动态映射。
2. **接口无枚举值**：`ref` 只给实体标识，下拉选项需另查维度/枚举/业务对象接口；`text` 类型字段的取值域也不在本接口中。
3. **无版本与分页**：响应没有 `version`/`updatedAt`/`total`，也没有分页参数，建议本地按 corpId + 抓取时间落缓存，用「字段数 + name 集合哈希」判断是否需要刷新。
4. **英文名覆盖率低**：284/406 条 `enLabel` 为空，国际化场景需按 `enLabel → cnLabel → label` 回退。
5. **空值/异常值容错**：`ability` 存在「空字符串」与「属性缺失」两种形态；`canAsDimension` 可能缺失；`number.scale/unit` 可能为 `null`；个别 `label` 含前导/尾随空格（如 `" 摊销方式"`、`" 收票方地址"`）。
6. **复合结构需递归解析**：`list<complex>` 的 `elemType.fields` 是完整字段定义，可递归转换为树；`dynamic` 字段必须结合模板（`specificationId`/`dataLinkTemplateId`）二次获取。
7. **专用组件类型不可解析**：`invoice`、`permitOrder`、`checkingBillInfo`、`splitCalculation`、`profitAndLossSummary`、`corporateExpenseCard`、`reconcileResult`、`supplier` 仅给类型名，需要按其业务语义单独建模。
8. **敏感字段**：`sense`（敏感字段）、`u_*金额`、`u_*账号` 等可能涉及权限控制，展示/导出前应结合字段权限策略。

### 8.1 字段与前端控件的关系（补充）

本文档描述的只是**数据语义**，不包含前端控件类型。控件定义在单据模板接口 `/api/form/v2/specificationGroups` 中：

- `specification.components[].type` 才是控件类型（18 种：text、textarea、select、money、date、details…）；
- `components[].field` 与本接口的 `name` 一一对应（实测 150 个模板字段 100% 命中）；
- `components[].configs` / `defaultValue` / `priority` 提供必填、隐藏、默认值、联动等渲染配置。

渲染表单需要 **propertySet（字段语义）+ specificationGroups（控件绑定）联查**，详见 [易快报单据模板(specificationGroups)分析.md](易快报单据模板(specificationGroups)分析.md)。
