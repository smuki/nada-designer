## 1. 配置模型与规模

### 4.2 显隐与权限

| 配置项 | 含义 | 取值 / 观察 |
| --- | --- | --- |
| `hide` | 默认是否隐藏 | true 280 / false 417（隐藏多为自动预填字段） |
| `hideVisibility` | 隐藏时的例外可见范围（谁可以看见） | fullVisible=true 272 / false 425 |
| `hideBlacklistVisibility` | 隐藏黑名单可见范围 | fullVisible=true 696 / false 1 |
| `visibility` | 组件级整体可见范围（本数据仅 details，且为 null） | 仅 details/requisitionDetails 25 个，全为 null |
| `visibleStaffSelection` | 可见人员选择范围（details，null） | 仅 details/requisitionDetails 25 个，全为 null |

`hideVisibility` / `hideBlacklistVisibility` 的结构与模板级 `visibility` 相同：

```json
{
  "fullVisible": false,
  "staffs": ["corpId:staffId"],
  "roles": [],
  "departments": ["corpId:deptId"],
  "departmentsIncludeChildren": true
}
```

- `hide=true` 表示默认隐藏，`hideVisibility` 描述“不隐藏的例外人群”（谁可见）；
- `hideBlacklistVisibility` 描述“隐藏黑名单”（黑名单内的人看不到）。

## 5. 默认值、优先级与动态配置

### 5.1 `defaultValue` 默认值

697 个字段控件都有 `defaultValue` 对象，按 `type` 分 5 种：

| `type` | 数量 | 说明 |
| --- | --- | --- |
| `none` | 392 | 不设默认值，留空待填 |
| `predefine` | 130 | 平台预定义值（提交人、部门、日期、默认主体等） |
| `formula` | 93 | 公式计算（EKB 表达式） |
| `constant` | 61 | 固定常量 / 固定选项 |
| `sum` | 21 | 明细汇总到表头（如明细金额合计） |

`defaultValue` 对象结构：

| 属性 | 说明 |
| --- | --- |
| `type` | none/predefine/formula/constant/sum |
| `value` | 值本体：predefine 为标记串、formula 为表达式、constant 为对象、sum 为明细字段名 |
| `customRuleId` | 自定义规则 ID（本数据全 null） |
| `assignValueTo` | 赋值目标标记（null 87 个、BASE 6 个） |

`predefine` 的取值（出现次数）：

| 值 | 次数 | 含义（按命名推测） |
| --- | --- | --- |
| `submit.date` | 50 | 提交日期 |
| `submitter` | 35 | 提交人 |
| `submit.department` | 27 | 提交人部门 |
| `entity.default` | 17 | 默认主体 |
| `submit.requisition` | 1 | 提交的申请单 |

`formula` 中使用的函数（公式表达式支持函数调用与字段引用）：

| 记号 | 次数 | 说明 |
| --- | --- | --- |
| `$字段` | 194 | 反引号包裹字段名进行字段引用，如 `$提交人`.name |
| `to_Str()` | 25 |  |
| `format()` | 15 |  |
| `day_diff()` | 1 |  |
| `month_add()` | 1 |  |
| `if()` | 样例可见 | 条件表达式（样例：if (`$付款金额`.本位币 &gt;=2000) {…}） |

公式示例（真实数据）：

```text
`$提交人`.name + "申请" + `$ 摊销方式`.name + "确认"      // 标题
day_diff(`$结束时间`, `$开始时间`) + 1                    // 总天数
month_add(`$借款日期`, 1)                                   // 还款日期
if (`$付款金额`.本位币 >= 2000) { return false } else { return true }
```

### 5.2 `priority` 取值优先级

多数控件带 `priority` 数组，声明 4 类取值来源的优先级数值：

| 取值来源 `type` | 含义 |
| --- | --- |
| `MANUALLY_FILL_IN` | 手工录入 |
| `LINKAGE_ASSIGNMENT` | 联动赋值（其他字段带出） |
| `AUTOMATIC_CALCULATION` | 自动计算（默认值/公式） |
| `COST_STANDARD` | 费用标准/制度取值 |

数据观察：`priority` 数组 629 个、null 43 个；details/requisitionDetails 无此配置。共 3 种组合：

| 组合 | 数量 |
| --- | --- |
| MANUALLY_FILL_IN=5 / LINKAGE_ASSIGNMENT=10 / AUTOMATIC_CALCULATION=15 / COST_STANDARD=20 | 604 |
| MANUALLY_FILL_IN=5 / AUTOMATIC_CALCULATION=10 / COST_STANDARD=15 / LINKAGE_ASSIGNMENT=20 | 24 |
| LINKAGE_ASSIGNMENT=5 / MANUALLY_FILL_IN=10 / AUTOMATIC_CALCULATION=15 / COST_STANDARD=20 | 1 |

### 5.3 `configs` 动态属性

`components[].configs` 是**运行时动态配置**，数组元素结构：`{ property, valueType, formula, ability }`。

| 统计项 | 观察 |
| --- | --- |
| 使用动态配置的控件 | 61 / 697 |
| `property=hide` | 55 |
| `property=optional` | 39 |
| `property=setip` | 4 |
| `valueType` | BOOLEAN / STRING |
| `ability` | `caculate`（平台侧拼写，应为 calculate） |

示例：

```json
{
  "property": "hide",
  "valueType": "BOOLEAN",
  "formula": "`$付款金额`.本位币 <= 2000",
  "ability": "caculate"
}
```

含义：公式成立时隐藏该控件。`optional` 则切换必填状态。使用动态配置的模板示例：差旅费和市内交通费快速报销单、个人费用报销单、二手车销售统一发票「自动开票」、发票申请单「自动开票」、银行账号申请等。

## 8. 观察与接入建议

1. **配置项虽多，常用集中**：84 项里只有 6 项所有控件通用，字段控件常用约 20 项，其余多为类型专属或“保留字段”。
2. **恒为 false/true 的字段**：`readonly`/`showInDetails`/`defaultField` 恒 false、`copyable` 恒 true、`allowInteriorStaff` 恒 true——渲染时可按默认处理。
3. **“隐藏 + 默认值”是主模式**：280 个控件 `hide=true`，其中 138 个带默认值（84 个为公式），说明大量字段是“自动计算/预填并隐藏”的。
4. **只读展示用 `editable=false`**：共 180 个（text 59、select 55、money 28、date 22 等），不是 `readonly`。
5. **动态配置用得不多**：仅 61/697 个控件有 `configs`，集中在发票/付款/费用报销类模板；其余字段为静态配置。
6. **依赖高度集中**：70 条依赖中指向 `submitterId` 的 50 条，方向以 forward 为主，典型是“人员/部门/上级/法人实体”随提交人联动。
7. **外部引用需要二次查询**：`assignmentRule`（79）、`filterId`（9）、`referenceData`（业务对象模板）、`predefine` 标记等都需要再查平台对应配置。
8. **表达式引擎是硬依赖**：`defaultValue.formula` 使用反引号字段引用与 `to_Str`/`format`/`day_diff`/`month_add`/`if` 等函数，渲染端必须实现子集或降级。
9. **空值语义**：`null` 表示“未配置”（如 `visibility`、`showTypeByRole`），字段缺失表示“该控件类型不支持该项”（如 details 没有 `priority`），不能一视同仁。
10. **渲染判定顺序建议**：`hide` → 执行 `configs` 公式覆盖 hide/optional → `optional` 决定必填 → `editable` 决定只读 → `dependence`/`filterId` 决定选项范围 → `defaultValue` → `dependence` 赋值。
11. **与 propertySet 联查**：`component.field` 对应 `propertySet.name`，据此取字段语义与选项来源（ref entity → 维度/枚举接口）。
12. **版本缓存**：模板随配置变化，建议按 `specificationId + version` 缓存控件配置。
