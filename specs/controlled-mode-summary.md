# 受控字段模式 · 一页摘要

> 配套完整规格：[controlled-mode.md](controlled-mode.md)（v0.17，评审留痕用，实现时不必通读）

## 一句话

设计器增加「受控模式」：字段清单来自业务对象的元数据，面板拖入即生成普通组件；字段名不可改、同一表单不重复、不可复制。默认「自由模式」行为完全不变。

## 规则（受控模式）

1. 开关 `designMode: 'free' | 'controlled'`，实例级、挂载时定死、不可切换、不落盘。
2. 一页一个业务对象 `modelId`（原 `businessObject`），随页面 JSON 保存；打开页面以 JSON 为准。
3. 面板 = 业务字段（来自元数据）+ 布局 `card`/`row`/`tabs` + `form`；不出现 input/number 等原始输入组件。
4. 拖入：`type` 按数据类型映射；`id = 作用域id_字段名`；`label` 取元数据；字段名只读、`label` 可改。
5. 同一作用域内字段唯一：落点校验，重复直接摘除，不写撤销记录。
6. 复制 / 粘贴 / Ctrl+D / Ctrl+X / 大纲复制：静默禁止；剪贴板里的文本复制（复 ID、复 JSON）不受影响。
7. 跨表单拖拽 = 移动：重算 id，并同步改写动作里对该节点的引用。
8. 保存/导入 JSON 带 `modelId`；导入不同对象会重载元数据，失败不应用；撤销/重置后归属不丢。
9. 运行时不需要元数据，EBuilder 照常渲染；预设属性已写进节点。

## 实施（5 步，约 8–9 人日）

1. 类型与元数据加载（Loading / 失败重试 / 缓存）。
2. 面板业务字段 + 拖入构造 + 属性面板字段只读。
3. 约束：唯一性、复制禁止、跨表单移动、大纲禁用。
4. 持久化与导入（modelId 全链路）。
5. 文档、demo（三套 UI 库）、单测、回归。

## 三个真风险

1. **同字段拖两次会生成相同 id** —— 会连带搞乱选中/撤销/大纲，所以校验必须硬拦截，不能只提示。
2. **拖拽是"先插入、后拿落点"** —— 只能做"落点校验 + 摘除回滚"，面板无法提前置灰（已按此定案）。
3. **元数据会变** —— 节点自带完整 schema，字段被删也不影响已放置节点，只影响面板。

## 现在只需要你

扫一眼规则 1–9 有没有硬伤；没有就按第 1 步开工。
